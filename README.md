# MacPolish

[EN](./README.en.md)

MacPolish 是一个原生 macOS 清洁工具，用于在擦拭 MacBook 时同时保护屏幕和键盘输入。它将“擦屏幕”和“擦键盘”整合到一个应用里，支持整机清洁、仅屏幕清洁和仅键盘清洁三种模式。

## 下载与安装

[下载最新版本](https://github.com/JiGuangYa/MacPolish/releases/latest)。支持 macOS 13 及以上，安装包同时包含 Apple silicon 与 Intel 版本。

打开 `MacPolish.dmg`，将 MacPolish 拖入“应用程序”；也可以使用 `.pkg` 安装器。Release 附带 `.zip`、SHA-256 校验文件和构建清单。目前安装包使用本地 ad-hoc 签名，尚未经过 Apple 公证。

## 功能特性

- 原生 macOS `SwiftUI + AppKit` 应用
- `Whole Mac`、`Screen Only`、`Keyboard Only` 三种清洁模式
- `Whole Mac` 模式下让所有显示器变黑并拦截本地键盘输入，全局拦截可用时增加系统范围的键盘保护
- `Screen Only` 模式下只黑屏，键盘保持可用
- `Keyboard Only` 模式下保持屏幕可见并全局禁键，依赖“辅助功能”权限
- 可记住上次使用的模式，并设置退出后返回主窗口、退出提示和控件淡出时间
- 菜单栏可快速开始／结束清洁和重新打开主窗口，清洁期间始终保留入口
- 清洁界面显示运行时间和实际键盘保护范围，自动结束后说明原因
- 主窗口清洁中的退出按钮与长按倒计时固定在底部，最小窗口中也无需滚动寻找
- 清洁计时和防误触延迟使用单调时钟，不受系统日期调整影响
- 设置窗口可纵向调整大小；淡出滑块提供辅助功能名称、秒数及每次 0.1 秒的调节
- VoiceOver 或切换控制开启时保留黑屏退出控件；关闭后恢复原有淡出延迟，不更改设置
- 定期检查全局键盘拦截；权限被撤销或拦截失效时自动结束会话
- 检测 macOS 安全输入并提示恢复步骤，避免不必要的重新授权或重启
- 仅有应用内保护时，切换到其他应用会自动结束清洁
- 重新打开时等待新实例完成启动；失败时保留当前应用，并防止重复请求
- 隐藏应用、睡眠、切换用户或显示器配置变化时自动结束清洁并释放键盘
- 仅在显示器身份、尺寸、位置或缩放实际变化时结束会话，菜单栏图标变化不会误触发退出
- 根据 macOS 首选语言列表自动切换界面语言
- 已支持英文、简体中文、繁体中文、日文、韩文、法文、德文、西班牙文、意大利文、巴西葡萄牙文
- 生成同时包含 Apple 芯片和 Intel 版本的通用 `.app`、`.pkg`、`.dmg`、`.zip` 安装包
- 发布前校验架构、签名、语言资源和归档内容，并生成 SHA-256 校验值；失败时保留上一份产物

## 使用与退出

需要 macOS 13 或更高版本。

| 模式 | 键盘行为 | 退出方式 |
| --- | --- | --- |
| 整台 Mac | 拦截应用内按键；全局拦截可用时增加系统范围保护 | 移动鼠标显示“完成”并点击，或长按 Control + Option + Esc 三秒 |
| 仅屏幕 | 保持键盘可用 | 点击屏幕；MacPolish 在前台时也可按 Esc |
| 仅键盘 | 系统范围拦截，需要辅助功能权限 | 点击主窗口中的“退出清洁”、使用菜单栏图标，或长按 Control + Option + Esc 三秒 |

“仅屏幕”开始后会短暂忽略启动时的连点及松开动作，防误触时间遵循系统双击间隔（至少 0.45 秒）。之后再点击即可结束；应用在前台时，Esc 始终可退出。

从菜单栏或“清洁”菜单开始“整台 Mac”或“仅键盘”时，MacPolish 会先打开主窗口，等待窗口在当前桌面可见且获得焦点，再开始清洁。这也确保整机清洁需要应用内键盘保护时，应用已在前台。等待期间可以取消；若五秒内未能就绪，键盘保持可用并显示失败提示。“仅键盘”的授权和刷新操作也会先打开主窗口，但不会在权限就绪后自动开始清洁。仅屏幕清洁无需先恢复主窗口。

在锁键的两种模式中，按住 **Control + Option + Esc 三秒**也可结束清洁。界面会显示倒计时；松开任一组合键、按下其他键或发生拦截中断都会取消，下一次需要重新按满三秒。普通 Esc 仍被拦截，避免擦拭误退出。关闭退出提示不会隐藏正在进行的倒计时；菜单展开或拖动控件期间，倒计时仍会继续。

使用“仅键盘”前，在“系统设置 → 隐私与安全性 → 辅助功能”中为 MacPolish 授权。授权按钮与系统使用相同的“辅助功能”名称。MacPolish 不会保存或上传输入内容，主窗口和设置页的授权区域也会说明这一点。若应用提示需要重新打开，按提示重新打开后再开始清洁。应用会显示进度，确认新实例完成启动后才退出当前实例；若失败或超过 15 秒，当前应用保持可用，主窗口和设置页都会显示重试提示。

“仅键盘”模式还会在主窗口关闭、最小化，或切换桌面后主窗口不在当前桌面时结束，避免退出按钮消失后继续禁键。如果切换的是另一台显示器上的桌面、主窗口仍可用，则继续清洁。桌面切换也会取消尚未完成的窗口恢复请求。关闭窗口、隐藏应用、睡眠、切换用户、桌面或显示器变化所触发的结束不会重新弹出主窗口或抢占前台；恢复后需手动开始新的清洁会话。

若全局键盘保护在清洁中失效，应用会结束会话并显示恢复指引；是否返回主窗口遵循设置。菜单展开或拖动控件期间仍会检测拦截失效、权限撤销和安全输入。无法全局拦截的“整台 Mac”会明确标为“应用内保护”，系统快捷键仍可能生效。应用内保护会在其他应用切换到前台时结束，且不会抢回焦点。

密码输入框和部分应用使用的 macOS 安全输入可能阻止键盘拦截，即使辅助功能已授权也会受影响（[Apple 技术说明](https://developer.apple.com/library/archive/technotes/tn2150/_index.html)）。MacPolish 会识别这一暂时状态，结束受影响的会话，并避免打断密码输入。完成密码输入或关闭启用安全输入的应用后，刷新状态即可重新使用键盘清洁；期间仍可使用屏幕清洁和带应用内保护的整机清洁。

## 开发

```bash
swift build
swift run MacPolishVerification
swift run MacPolish
```

`MacPolishVerification` 检查权限流程、会话中断、失败清理、设置持久化和语言资源；还通过注入权限与拦截器接口，使用未发送到系统的真实 `CGEvent` 对象验证生产键盘服务，覆盖修饰键／媒体键过滤、超时恢复、安全输入、旧回调和资源释放。隐藏的原生窗口验证输入处理、鼠标退出、启动连点与排队点击的防误触，以及黑屏视图的固定尺寸（含负坐标显示器布局），真实定时器验证提示与控件淡出。菜单启动验证窗口延迟就绪、超时、取消、重复操作、权限变化和旧请求隔离。长按退出覆盖三秒边界、松键取消、重复按键、旧会话隔离、全局与本地输入路径及真实倒计时。嵌套事件循环验证菜单／拖动期间的长按退出和保护检测，以及松键、停止或释放对象后的定时器清理。重新打开流程覆盖启动失败、等待就绪、超时、旧回调、重复请求和失败后继续使用。验证不申请权限、不安装全局拦截器、不向系统发送输入，也不显示桌面窗口。睡眠、前台切换和显示器变化通过注入通知验证；桌面切换使用隐藏窗口模拟 Space 归属，覆盖退出窗口离开、仍在当前桌面和取消待启动请求。应用内保护还验证了无前台焦点时拒绝开始。辅助工具状态通过注入事件和真实淡出定时器验证，系统观察接口只做只读检查，不开关 VoiceOver 或切换控制。真实读屏播报、切换设备操作、桌面切换和硬件行为仍需在 macOS 上手动确认。

生成真实 SwiftUI 视图的离屏预览：

```bash
./scripts/render_previews.sh                 # 英文、简体中文、德文
./scripts/render_previews.sh ja ko zh-Hant   # 指定已支持的语言
```

每种语言生成 70 张浅色／深色预览，涵盖首次授权和权限被拒绝、清洁中、锁屏及长按退出倒计时、保护失效、安全输入、桌面切换后的结束提示、重新打开和主窗口恢复的进度与失败状态、窄窗口、最小高度的清洁与倒计时界面、设置页、完整展开的淡出选项、辅助工具开启后的持续退出控件及高对比度预览，输出到 `.build/previews/`。预览使用模拟服务，不显示桌面窗口，并检查实际生效的语言，避免英文回退掩盖排版问题。最小窗口的首次授权预览会滚动到底部，以检查键盘卡片中的说明和按钮。

高对比度预览在验证程序内使用 SwiftUI 的内部环境覆盖接口，注入对比度、减少透明度和减少动态效果，并检查实际生效值。这些接口不进入正式应用，也不改变系统偏好；真实系统开关与辅助设备的交互仍需实机验证。

在已登录的桌面会话中验证真实 macOS 应用启动流程：

```bash
./scripts/verify_relaunch.sh
```

脚本创建临时后台测试应用，通过生产重启服务启动两个独立实例，确认启动和交接后关闭测试进程。它不打开 MacPolish、不申请权限、不拦截输入，也不退出验证程序。即使测试中断，测试应用也会在 20 秒后自动退出。CI 会运行 Debug 和 Release 验证；真实启动流程作为单独的本地检查。

在已登录的桌面会话中验证真实窗口与菜单操作：

```bash
python3 scripts/verify_window_flow.py
python3 scripts/verify_window_flow.py --configuration release
python3 scripts/verify_window_flow.py --settings-only --output .build/settings-verification.json
python3 scripts/verify_window_flow.py --shield-only --output .build/shield-verification.json
```

这是单独启用的原生界面检查，会短暂显示测试窗口和菜单，使用与正式应用相同的 SwiftUI 场景。13 项检查覆盖菜单开始／结束、关闭后重开、最小化后恢复、窗口关闭／最小化时释放保护、Esc 菜单绑定、权限恢复、整机清洁开始前恢复前台窗口、临时菜单栏入口，以及设置滑块的辅助功能读数、增减、禁用状态和窗口缩放。辅助功能检查只读取测试应用自身的节点，并操作其独立设置。黑屏退出视图在普通小窗口内渲染，验证控件在模拟辅助工具状态下持续可访问、关闭后恢复淡出，以及辅助功能的按下动作能调用退出。键盘、黑屏和权限服务使用模拟实现，不拦截键盘、不覆盖屏幕、不申请权限，也不向系统发送输入。测试使用独立设置，完成后关闭自身；若仍在前台，会请求返回先前的应用。

运行时需让测试应用保持前台，并避免同时执行其他界面测试；未获得焦点会报告失败，键盘保持可用。结果写入 `.build/window-verification.json`，包含构建类型、验证时间和窗口诊断；可用 `--output` 指定路径。普通验证与 CI 不运行这个可见界面检查。全局键盘拦截和物理显示器变化仍需实机验证。

## 打包

```bash
./scripts/package_release.sh
```

脚本可从任意工作目录调用。它先在临时目录构建 `arm64 + x86_64` 通用应用，目标系统为 macOS 13，然后检查实际封装到 DMG、PKG 和 ZIP 中的应用。检查涵盖双架构、最低系统版本、系统库依赖、十种语言资源、签名、安装路径和归档内容一致性；全部通过后才替换 `dist/` 中的产物。构建或检查失败不会删除旧包，文件替换失败会回滚。

可指定版本和构建号：

```bash
APP_VERSION=1.2.0 APP_BUILD=3 ./scripts/package_release.sh
```

版本必须为三个数字分量，构建号必须为正整数。`dist/release-manifest.json` 记录版本、架构、源码提交与未提交状态、签名类型和归档校验值。可以独立检查已有产物：

```bash
python3 scripts/verify_release.py dist
(cd dist && shasum -a 256 -c SHA256SUMS)
python3 scripts/test_release_tools.py
```

目前产物使用本地 ad-hoc 签名，**尚未使用 Developer ID 签名或通过 Apple 公证**。检查通过表示文件与签名保持完整，不表示已经获得 Developer ID 签名或公证。CI 会构建并检查通用安装包；这不替代在目标 macOS 版本和真实 Intel 硬件上的运行验证。
